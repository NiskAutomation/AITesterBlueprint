# SOP: Generate Test Cases

## Goal
Generate structured test cases from a Test Plan + JIRA ticket data using deterministic templates.

## Inputs
- `test_plan`: JSON object (generated by Test Plan SOP)
- `jira_ticket`: JSON object (original JIRA ticket)
- `mode`: `"llm"` or `"template"` (default: `"template"`)
- `groq_key`: Optional GROQ API key

## Tool Logic (Template Mode)
1. Analyze the Test Plan feature and JIRA ticket description
2. Generate test cases across categories:
   - **Functional (Positive)**: 3-5 test cases for core happy paths
   - **Boundary**: 2-3 test cases for limits, ranges, edge values
   - **Negative**: 2-3 test cases for invalid inputs, error handling
   - **Security**: 1-2 test cases for auth, injection, XSS
   - **Integration**: 1-2 test cases for component interaction
   - **Regression**: 1-2 test cases for previously fixed issues
3. For each test case:
   - Generate unique ID: `{jira_id}_TC_{001..n}`
   - Map priority from test plan priority strategy
   - Write description based on feature + scenario
   - Define pre-conditions from ticket data
   - Write 3-5 steps with clear action + expected result
   - Set expected result based on ticket acceptance criteria
   - Mark automation feasibility
   - Add traceability to JIRA ticket
4. Apply anti-hallucination rules:
   - Only test what is mentioned in the ticket
   - No invented UI elements or API endpoints
   - Unknown = "Insufficient information"
   - Label assumptions

## Test Case Generation Rules

### Functional (Positive)
- Test the main happy path described in the ticket
- Test each acceptance criterion as a separate test case
- Test standard workflows

### Boundary
- Test minimum/maximum values for numeric fields
- Test empty strings for text fields
- Test maximum length for strings
- Test date boundaries (past, future, today)

### Negative
- Test missing required fields
- Test invalid data types
- Test unauthorized access
- Test invalid format inputs

### Security
- Test SQL injection patterns
- Test XSS payloads
- Test authentication bypass
- Test session handling

### Integration
- Test interaction with other components
- Test end-to-end flow
- Test data consistency across systems

### Regression
- Test areas previously reported as buggy
- Test critical business flows

## Tool Logic (LLM Mode)
1. Build RICE-POT prompt:
   - Role: "You are an expert QA Test Engineer with 10+ years experience"
   - Instructions: "Generate comprehensive test cases from the test plan and JIRA ticket"
   - Context: Test Plan + JIRA ticket JSON
   - Example: Reference test case structure
   - Parameters: "Be deterministic, traceable, no hallucinations"
   - Output: JSON array of test cases
   - Tone: "Professional, precise, structured"
2. Call GROQ API
3. Parse and validate JSON
4. Return structured test cases

## Edge Cases
- **Empty test plan**: Return error, cannot generate test cases
- **LLM timeout**: Fallback to template mode
- **Invalid JSON**: Attempt repair, fallback to template
- **Missing acceptance criteria**: Generate basic functional tests, flag as "limited info"
- **No description**: Generate from summary only

## Validation
- Minimum 5 test cases per plan
- Maximum 50 test cases per plan
- Each test case must have at least 2 steps
- Each test case must have expected result
- No duplicate test cases
- All test cases trace to JIRA ticket

## Output Format
Matches Test Case schema in gemini.md

## Quality Rules
1. Test case IDs must be sequential
2. Priorities: High/Medium/Low (max 40% High, min 20% Low)
3. Steps must be actionable and verifiable
4. Expected results must be specific and measurable
5. No hallucinated UI elements, APIs, or behavior
6. Traceability: Every test case must reference the JIRA ticket
